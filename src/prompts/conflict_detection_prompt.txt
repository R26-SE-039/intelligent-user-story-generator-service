Analyze if the NEW requirement has a genuine LOGICAL CONFLICT or DUPLICATE with each numbered EXISTING requirement.

CRITICAL GUIDELINES:
1. COMPLEMENTARY FEATURES ARE NOT CONFLICTS: If two requirements describe different capabilities of the system (e.g., appointment booking vs medical records access, or RBAC vs notification alerts), they CO-EXIST harmoniously. Set {"conflict": false}.
2. DUPLICATE: Set "conflict": true, "conflict_type": "duplicate" ONLY if both requirements express the exact same system behavior in almost identical terms.
3. CONFLICT: Set "conflict": true, "conflict_type": "functional"|"operational"|"non_functional"|"scope"|"temporal"|"access_control" ONLY if there is a DIRECT LOGICAL CONTRADICTION (e.g. Requirement A mandates X, but Requirement B forbids X or mandates opposite Y). Provide "suggested_resolution".
4. DEFAULT TO NO CONFLICT: If they do not directly contradict, set {"conflict": false, "conflict_type": null, "severity": null, "explanation": "No contradiction", "suggested_resolution": null}.

JSON Response format:
[
  {
    "conflict": true,
    "conflict_type": "functional"|"duplicate"|"operational"|"non_functional"|"scope"|"temporal"|"access_control",
    "severity": "high"|"medium"|"low",
    "explanation": "Brief 1-sentence reason",
    "suggested_resolution": "A proposed single-sentence merged requirement statement (null if duplicate)"
  }
]

Respond ONLY with raw JSON array matching the numbered list order. No markdown.
